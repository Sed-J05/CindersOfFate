## Prompt 0 — Kickoff & project setup (2026-10-17)

- **D-001 · Unity version = 6000.0.32f1 (Unity 6 LTS).** Detected from `ProjectSettings/ProjectVersion.txt`. All code uses Unity 6 APIs: `Rigidbody2D.linearVelocity`, `linearDamping`, `FindFirstObjectByType` / `FindObjectsByType`, URP 17.0.3 `Light2D`, Input System 1.11.2, TextMeshPro via `com.unity.ugui` 2.0.0. — *If the project is downgraded to 2022.3, swap to `.velocity` / `FindObjectOfType`.*
- **D-002 · Project folder / product name stays "cinders of fate".** The Unity project was created under that name, not "Shatranj". Renaming the folder, `.sln` and `productName` now gains nothing and risks breaking the human's open editor. — *`Build Windows Player` (Prompt 18) will set `productName = "Shatranj"` for the build only; the folder keeps its name.*
- **D-003 · Layer slot assignment:** Ground 8, OneWay 9, Player 10, PlayerHurtbox 11, Enemy 12, EnemyHurtbox 13, PlayerAttack 14, EnemyAttack 15, Hazard 16, Interactable 17, RoomBounds 18, Ignore 19. Our `Ignore` layer (visual-only objects, collides with nothing) is distinct from Unity's built-in `Ignore Raycast`. Indices are `const` in `GameLayers` so masks are compile-time. — *Change the table in `GameLayers.All`, re-run Setup Project; the tool refuses to overwrite an occupied slot and reports it.*
- **D-004 · Sorting layer "Light/Overlay" is named `LightOverlay`.** A slash in a sorting-layer name is legal but confusing in menus and string paths. Unity's `Default` sorting layer cannot be removed; it stays at index 0 (behind `Parchment`) and nothing in the game uses it. — *Rename in `GameLayers.Sorting`, re-run Setup Project (IDs of existing layers are preserved; a renamed layer is created new).*
- **D-005 · Collision matrix rules** (only `Default` + our 12 layers are touched; built-in TransparentFX/Water/UI are left alone):
  - Player body ↔ Enemy body **do not collide** (Hollow-Knight pass-through). Contact damage is an `EnemyAttack` trigger on the enemy hitting the `PlayerHurtbox` trigger.
  - Enemy ↔ Enemy **do not collide**; Phase 2 "don't stack" is handled by separation steering, which avoids physics jitter.
  - `PlayerAttack` / `EnemyAttack` collide with `Ground` only so projectiles can die on walls; melee hitboxes filter ground hits in code.
  - Hazards damage only via `PlayerHurtbox`; they do not block the body and do not hurt enemies.
  - `Default` collides with `Default`, `Ground`, `Player`, `Enemy` (forgiving for unassigned objects) but never with hit/hurt/trigger layers.
  - `Ignore` collides with nothing.
  — *Edit `GameLayers.CollisionPairs`, re-run Setup Project.*
- **D-006 · Tags limited to `Player`, `Enemy`, `Boss`, `Interactable`.** Tags exist only for editor validation and debug tooling; gameplay uses layers and component lookups (CLAUDE.md §4). — *Add to `GameLayers.Tags.All`.*
- **D-007 · Settings are written twice: `SerializedObject` on the ProjectSettings singletons (persists to disk) and the runtime API (`Time.fixedDeltaTime`, `Physics2D.gravity`).** The collision matrix uses `Physics2D.IgnoreLayerCollision`, which is what Unity's own Physics 2D inspector calls and which persists to `Physics2DSettings.asset`; the tool verifies each pair afterwards and reports any that did not stick.
- **D-008 · `.gitignore` = GitHub's standard Unity template plus `/[Bb]uilds/`.** Setup Project creates it if missing and appends any missing essential pattern; it never deletes lines. The project is **not yet a git repo** (`git init` is a human step; see Docs/02 §1).
- **D-009 · `.gitkeep` files mark empty folders.** Unity ignores dot-files, so they create no `.meta` churn and don't show in the Project window. Setup Project re-adds them idempotently; they can be deleted once a folder has content.
- **D-010 · `Assets/Scenes/SampleScene.unity` and the template's `InputSystem_Actions.inputactions` are left untouched.** `Build All Scenes` (Prompt 8/11) will own the Build Settings scene list; input actions are built in code (CLAUDE.md §3), so the asset is simply unused.
- **D-011 · URP / Quality tweaks listed for Setup Project in Docs/02 §10 are deferred to Prompt 10 (visual rig).** Prompt 0 asked for a specific list; the renderer settings depend on the parchment/flame rig design and would be revisited anyway.
- **D-012 · Active Input Handling is reported, not changed.** It is already `Both` in this project. Changing it requires an editor restart, so the tool only warns if it is wrong.
- **D-013 · `GameLayers` is also the data source for Setup Project and the future Validate Project.** Editor scripts (Assembly-CSharp-Editor) reference runtime code, so there is one table, no duplication, and `GameLayers.Validate()` can be called from both.
- **D-014 · Unity 6 serializes some ProjectSettings fields as uint / bool / double.** `SerializedProperty.intValue` / `floatValue` reject those with "type is not a supported int/float value" (seen on the first Setup Project run: sorting-layer `uniqueID` is uint, `Fixed Timestep` is not a plain float). `SetupProject` now uses type-aware helpers (`GetInt` / `SetInt` / `SetFloat`) that inspect `propertyType` + `numericType`, and every stage is isolated so one failure cannot hide the rest of the summary. Sorting-layer IDs are 31-bit positive FNV hashes; a re-run repairs any non-Default layer that ended up with ID 0. — *Reuse these helpers in every future editor tool that touches ProjectSettings.*
- **D-015 · Fixed timestep is written as the exact rational 1/60 s.** Unity 6 serializes `TimeManager.Fixed Timestep` as a rational time (`m_Count` ticks at `m_Rate.m_Numerator / m_Rate.m_Denominator` per second), not a float. Setup Project writes count 1, rate 60/1, i.e. exactly 1/60 s rather than the doc's rounded 0.01666. — *Change `FixedStepHz` in `SetupProject.cs`.*

## Prompt 1 — Core framework (2026-10-17)

- **D-016 · Three assembly definitions: `Shatranj.Runtime`, `Shatranj.Editor`, `Shatranj.Tests.EditMode`.** EditMode tests cannot reference Unity's predefined Assembly-CSharp, so the runtime code needs its own asmdef; once it exists the editor folder needs one too. asmdefs are JSON config, not Unity YAML, so CLAUDE.md §2.2 is respected. Side effect: faster recompiles. — *Later folders under `Assets/Scripts` are picked up automatically; new editor tools go under `Assets/Editor`.*
- **D-017 · ScriptableObject configs use public fields, not `[SerializeField] private` + getters.** Configs are pure data containers with 40–80 fields each; private fields would double every file for no encapsulation gain and make the editor generator clumsy. CLAUDE.md §4's `[SerializeField] private` rule still applies to every MonoBehaviour. — *If encapsulation is wanted later, wrap with properties without renaming the serialized fields.*
- **D-018 · Tween runs on a hidden `[TweenRunner]` MonoBehaviour that ticks a list in Update; no coroutines.** One Update for all tweens, no per-frame allocation, works on inactive objects, `unscaled` flag for UI/pause, `KillTweensOf(target)` for cleanup. In Edit mode (tests) a tween completes instantly so callers still get the end state.
- **D-019 · Debug hotkeys are split: `DebugHotkeys` (Editor/Development only, reads the keyboard) and `DebugCommands` (always compiled; flags + events).** Gameplay systems subscribe to `DebugCommands` without `#if` guards; the key reader is the only thing stripped from release builds. F4 and F9 are fully functional already; F2/F3/F5/F6/F8 raise requests that Prompts 2–12 act on.
- **D-020 · Hit-stop vs pause.** `HitStop` records the timescale it froze from and restores it when done; `GameManager.Pause()` cancels any hit-stop first and hit-stop never restores timescale while the game is paused, so a freeze can't un-pause the game. `SetState(Playing)` also resets `timeScale` to 1 as a safety net (CLAUDE.md §4).
- **D-021 · Numbers the docs leave unspecified (logged so tuning can revisit):** Knight approach speed 3 u/s (patrol 2); Thrower detect range 12 u and patrol 2.5 u/s; Lunger knockback = Crawler's 3 u/s; Kite dive active time 0.7 s and recovery 0.3 s; Bat dive active 0.6 s; Charger charge active 0.8 s, recovery 0.5 s; all boss `fairnessGap` 0.4 s except Colossus/Zulmat 0.6 s (doc value); boss `introDuration` 1.5 s; death slow-mo scale 0.25 (bosses) / 0.3 (player).
- **D-022 · Zulmat's stage-3 "combos" are modelled as the enrage block** (`enrageBelowFraction` 0.34, telegraphs −0.15 s, cooldowns ×0.8). The combo pairs themselves (Slash→Vine, Lunge→Swipe) are implemented in Prompt 15 using `minStage`.
- **D-023 · `BossMoveConfig.distanceBand` is a bitmask** (1 close, 2 mid, 4 far, 0 any) so the Colossus can list Big Arc Slash for close+mid and Jump Slam for mid+far in one entry each.
- **D-024 · `SaveSystem` writes atomically** (temp file then move) and `Load()` returns null on a missing or corrupt file instead of throwing; `GameManager.TryContinue()` treats null as "no save". `PathOverride` exists for tests.
- **D-025 · `Health` has an injectable clock** (`SetClock`) so i-frames are testable in EditMode without Play mode; default is `Time.time`. `Configure()` is the explicit initialiser because `Awake` doesn't run on `AddComponent` in Edit mode.
- **D-026 · `GameEvents` carries a few extra events beyond Docs/02 §4** (`OnBossHealthChanged`, `OnFinalBossDefeated`, `OnOrbTouched`, `OnBenchRested`, `OnCycleChanged`, `OnAbilitiesChanged`, `OnGameStateChanged`) because Prompts 5, 9, 15 and 16 name them.

## Prompt 2 — Player movement, input, camera, sandbox (2026-10-17)

- **D-027 · Player is split into `PlayerMotor` (physics primitives) and `PlayerController` (state machine).** Keeps both under the ~400-line limit and lets Prompt 3's combat code drive the motor without touching movement maths.
- **D-028 · Custom gravity:** `Rigidbody2D.gravityScale = 0`; the motor applies rise gravity (2h/t² ≈ 40 u/s²) while moving up and fall gravity (×1.5 ≈ 60) while moving down, clamped to 22 u/s. Jump velocity = 2h/t ≈ 16 u/s. These are derived properties on `PlayerConfig`, so changing apex height/time retunes everything.
- **D-029 · "Air control 90 %" is applied to the acceleration/deceleration *rates* in the air**, not to the max speed, so the player still reaches full run speed mid-jump but changes direction slightly slower. — *Flip to a max-speed multiplier in `PlayerMotor.ApplyRun` if the feel is wrong.*
- **D-030 · Movement input is digital** (stick/keys below `moveDeadzone` 0.3 = 0, otherwise ±1), matching the "A/D move" spec and Hollow Knight. Analog walking is out.
- **D-031 · One-way platforms use `PlatformEffector2D`** (surface arc 170°) on the `OneWay` layer; the ground check ignores one-way hits while moving up or when the surface is above the feet. No drop-through (Docs/02 §6 marks it optional).
- **D-032 · Wall-stick prevention is two-fold:** a zero-friction `PhysicsMaterial2D` on the capsule, and the motor zeroes any horizontal velocity into a wall it is touching (thin side box-casts 70 % of the capsule height, so steps don't register as walls).
- **D-033 · The sprite flips via the `Visual` child's `localScale.x`, not the root.** Flipping a Rigidbody2D root with negative scale re-syncs colliders every flip; keeping the body unflipped is cleaner. Prompt 3 mirrors hitbox offsets with `PlayerController.Facing`.
- **D-034 · Ground stick:** while grounded and not rising, vy is held at −`groundStickSpeed` (1 u/s) so the body keeps a resting contact and walks down 1-tile drops without a visible hop.
- **D-035 · Input buffers use `Time.time` timestamps** (jump 0.12 s, attack 0.15 s). Because hit-stop freezes `timeScale`, buffered presses survive hit-stop, which is what Hollow Knight does.
- **D-036 · K tap/hold lives in `PlayerInput`:** events `OnSpellTap` (released within 0.18 s), `OnHealHoldStart` (held past it, or pressed at all when fireball is locked) and `OnHealHoldRelease`. Prompt 3 subscribes.
- **D-037 · Camera numbers live in a new `CameraConfig` asset** (CLAUDE.md §4: no magic numbers). `CameraController` creates a default instance at runtime if none is assigned, so the camera never breaks.
- **D-038 · Camera centres 1.2 u above the player's feet** (`verticalOffset`) so a 1.7 u-tall puppet sits slightly below screen centre, Hollow-Knight style. Look-ahead 1.5 u follows facing, not velocity.
- **D-039 · `RoomBounds` notifies the camera directly on trigger enter** until Prompt 6's RoomManager takes over the room logic. `RoomBounds.WorldRect` is derived from transform position + size so the builder can place rooms by origin.
- **D-040 · Sandbox debug text uses legacy `UnityEngine.UI.Text` with the built-in `LegacyRuntime.ttf`**, not TextMeshPro, so the sandbox works before TMP Essentials are imported. Game UI (Prompt 5) still uses TMP.
- **D-041 · `SceneBootstrap` sets GameManager to Playing when a scene is opened directly in the editor**, only if the manager is still in its initial Menu state, so normal flow from the menu is untouched.
- **D-042 · Sprite-Lit-Default + one Global Light 2D in generated scenes** (CLAUDE.md §3). The placeholder `Square_White.png` lives in `Assets/Art/Placeholders/` and is never overwritten.
- **D-043 · Placeholder visuals use URP's built-in `Sprite-Lit-Default` material** referenced from the package path; no material assets are generated yet.
- **D-044 · Scene builders create the scene before loading any asset they will reference.** `EditorSceneManager.NewScene(…, Single)` unloads unused assets; config objects loaded before that call became dead references and were saved as `{fileID: 0}` (seen on the first Sandbox build: player and camera configs null, scene-object references fine). `SceneBuildUtil.SetReference` now refuses null/destroyed values and verifies the write, and `Build Sandbox Scene` reports whether both config references are set. — *Rule for every future builder: NewScene first, then load assets.*

## Prompt 3 — Player combat, soul, heal, dash, fireball (2026-10-17)

- **D-045 · Attack hitboxes are overlap queries, not trigger colliders.** `PlayerCombat` runs `Physics2D.OverlapBox` on the EnemyHurtbox layer during the active window (0.06–0.14 s after the press) and remembers what it already hit this swing. Deterministic at 60 Hz, no Rigidbody needed on targets, and F7 can draw exactly what is being tested. The fireball uses the same approach (moves by transform, overlap for enemies, overlap for walls).
- **D-046 · Melee `DamageInfo` carries direction with force 1.** Enemies apply their own knockback speed from `EnemyConfig` (Docs/04 gives it per enemy); the hit only says which way. Up attacks push up.
- **D-047 · Generic `DamageDealer` component for everything that hurts the player** (spikes now; enemy contact bodies, attack hitboxes and projectiles later). The player's hurtbox child reads it on trigger enter *and* stay, so standing in a hazard re-applies after i-frames — needed for lava (Docs/03 §7).
- **D-048 · Spike respawn:** damage + knockback as a normal hit, then after 0.35 s a 0.15 s fade, teleport to the last safe ground, fresh i-frames. Safe ground is recorded only while grounded, calm (Idle/Run/Land) for 0.5 s and *not overlapping a Hazard collider*, so i-frame strolls through spikes can't poison the respawn point.
- **D-049 · Death flow lives in `PlayerHealth`:** slow-mo (timeScale 0.3 for 0.6 s, unscaled wait) → fade → respawn at `RespawnPosition` with full hearts, soul 0 → fade in. `RespawnPosition` defaults to the spawn point; Prompt 6 benches set it. Bosses reset / enemies stay dead is Prompt 6+.
- **D-050 · Heal is refused at full hearts** (keeps soul for a fireball instead of burning 33 for nothing). Hollow Knight allows it; the doc is silent; this is friendlier. Heal also requires being grounded (doc says "rooted"). Soul is spent only on completion; an early release, damage, dash or death cancels for free.
- **D-051 · Fireball spawns at the moment of the K tap (release inside 0.18 s), not after the cast animation.** Responsiveness over fidelity; the Cast state (0.25 s) still roots a grounded player. — *Add a spawn delay in `PlayerSpells.TryFireball` if the placeholder-art swing looks wrong.*
- **D-052 · Dash exit zeroes velocity** ("velocity restored after" in Docs/03 §6 is read as: gravity resumes, no momentum carried), air dash resets on landing, cooldown counts from the end of the dash, i-frames come from `Health.GrantInvulnerability` so god mode and dash don't fight over one flag.
- **D-053 · Facing is locked during a swing** (the slash direction is committed); movement is still allowed, matching Hollow Knight.
- **D-054 · F4 toggles Phase 1 ↔ Phase 2 abilities** instead of only applying Phase 2 (superset of CLAUDE.md §6: press again to go back). Hearts refill when they grow, clamp when they shrink.
- **D-055 · Placeholder FX are runtime-generated sprites** (`PlaceholderSprites.Square/Circle`), pooled through one `SpriteFx` class for slashes, sparks, dash ghosts and impacts. `PlayerFxPools` exposes serialized sprite slots so Prompt 4 can drop in `Slash_Side`, `Slash_Up`, `Hit_Spark`, `SoulOrb`, `Fireball_Fly`, `Fireball_Impact` without touching callers.
- **D-056 · The training dummy revives 2 s after dying** so the sandbox never runs out of targets; its hurtbox is disabled while "dead".

## Prompt 4 — Placeholder art + animation pipeline (2026-10-17)

- **D-057 · No Unity Animator / AnimatorController. A runtime `SpriteAnimator` plays `SpriteClip`s from a `SpriteAnimationSet` ScriptableObject.** Reasons: `Play(name)` is all gameplay needs (states are code-driven, Docs/02 §6); no transition graphs to maintain across ~20 characters; frame timing uses scaled time so hit-stop freezes naturally; EditMode-friendly; artists changing frame counts only need a rebuild, not a controller edit. AnimationClips are therefore not generated at all (Docs/02 §10 "or SpriteAnimator data"). — *If a Timeline/Animator workflow is ever needed, a generator can emit clips from the same manifest.*
- **D-058 · Animation sets live in `Assets/Resources/Animations/<SetName>.asset`.** Runtime code can bind by name (`SpriteAnimationSet.Load("Protagonist")`), so the already-built Sandbox animates without a rebuild, and prefabs (Prompt 7) can still reference the asset directly. The folder is tiny: it holds references, not textures.
- **D-059 · `Assets/Data/AnimationManifest.json` is generated once from `ArtSpecTables` (Docs/06) and then owned by humans.** The generator menu keeps an existing file; delete it to regenerate. All three art tools read the JSON, never the C# tables.
- **D-060 · File layouts** (`SpriteSetDef.layout`): characters `Art/Characters/<Name>/<Anim>/<Name>_<Anim>_NN.png` (Docs/06 §2); FX and props `Art/<Folder>/<Name>/<Name>[_<Anim>]_NN.png` (Vine has Grow/Retract, Bench has Unlit/Lit/Activate); tiles, backgrounds, cutscene images and UI are flat in their folder, numbered only when animated (`FlameCore_00..05`, `Tile_Castle_Lava_00..03`, `Heart_Break_00..03`). Frame numbers are always two digits, so `Decor_<Theme>_00..03` and `CS2_Memory_01..06` (doc numbering kept for cutscenes).
- **D-061 · Pivots are set by the importer from the manifest** (bottom-centre for ground characters, props and Slash_Up; centre for flyers/FX/tiles/UI; bottom-left for Door; left-centre for Slash_Side and Giant_Swipe). Parchment and BG_* textures import with Repeat wrap for tiling; everything else Clamp. Max texture size is raised to 4096 for the 2400-px cutscene layers.
- **D-062 · Import settings are applied twice on purpose:** `ShatranjSpriteImporter` (AssetPostprocessor) catches every new or re-imported texture under `Assets/Art`, and `Import & Rebuild Animations` sweeps all existing textures to fix drift (files added before the postprocessor existed, or settings changed by hand). `Assets/Art/Placeholders` (the 32-PPU white square) is excluded.
- **D-063 · Rebuild reads frames from disk, not the manifest count.** If an artist delivers 10 Run frames instead of 8, the clip gets 10 and the report notes the mismatch; gaps inside a sequence are reported too. Sets are updated in place so GUIDs and scene/prefab references survive.
- **D-064 · Protagonist state → clip map** (`PlayerAnimator.ClipFor`): Idle, Run, Jump_Rise (holds last), Jump_Fall, Land, Attack_Side_A/B (alternation from PlayerCombat), Attack_Up, Cast, Heal_Charge (+ Heal_Release as a one-shot override on completion), Dash, Hurt, Death, Rest; Cutscene shows Idle until the cutscene system drives clips via `PlayClip`. Missing clip → Idle. With clips bound, the visual child sits at scale 1 on the root (256-px canvas, bottom pivot) and the placeholder eye is hidden; without a set the coloured-box tint fallback stays.
- **D-065 · Placeholder look:** silhouettes per style (biped, crawler, flyer, Zulmat with flame horns, crescents, discs, stars, vines, lava, tiles with bitmask lips, seamless parchment noise, vignette frame, radial flame glow, stalactite/tower backgrounds, hearts/rings/bars for UI), palette by phase (Docs/07), label `NAME` + `ANIM_NN` in a 5×7 pixel font, 2 px accent border, magenta pivot cross, ±4 px bob/leg swing per frame. Cutscene images are grey cards per Docs/08 §5.
